# Зовнішні агенти: агент тестів забирає screen object

> Частина [основної специфікації](../SPEC.md), розділ [11. Доступ: CLI, MCP, API](../SPEC.md#access); стосується також: [15. Агент станції](../SPEC.md#agent) ([agent.station-mcp](../agent.station-mcp/spec.md)), [6. Інспектор і автоматизація](../SPEC.md#inspector). Принципи продукту — у [розділі 13](../SPEC.md#rules), правила роботи з кодом — в [AGENTS.md](../../AGENTS.md); тут вони не повторюються.

- **ID:** `access.external-agents`
- **Статус:** implemented
- **Етап за документом:** v1 (зовнішні агенти)
- **Як зроблено:** [design.md](design.md)

## Проблема й користувач

Тести пише окремий агент — агент тестів у Kiro crew. Він працює в репозиторії автотестів, сам вирішує, коли йому потрібні екрани, і кладе код у репозиторій. Станція не має пхати йому файли: агент сам звертається до неї й забирає збережені пакети screen object ([autotests.screen-objects](../autotests.screen-objects/spec.md)).

MCP станції обслуговує вбудованого агента ([agent.station-mcp](../agent.station-mcp/spec.md), критерій 2) з токеном, який той отримує на кожен запуск. Цей крок відкриває станцію зовнішнім агентам на цьому Mac, лише на читання й лише для автотестів, з окремим токеном. Решта інструментів для зовнішніх агентів — пізніше.

## Критерії приймання

Підключення

1. **Дано** налаштування оператора, **тоді** доступ зовнішніх агентів за замовчуванням вимкнено; користувач вмикає його перемикачем на картці «Зовнішні агенти» і бачить готовий фрагмент `mcp.json` для свого агента з кнопкою «Копіювати».
   Тест: немає (перевірено наживо)
2. **Дано** увімкнений доступ, **тоді** зовнішній агент підключається командою `vision-inspector mcp` (міст stdio → станція). Поки доступ увімкнено, станція тримає в своїй теці даних файл із портом і тимчасовим токеном, який може читати лише цей користувач; міст знаходить станцію за ним. Токен діє до перезапуску станції, вимкнення доступу прибирає файл. Сервер, як і раніше, слухає лише `127.0.0.1`.
   Тест: `test/unit/autotests-external.spec.js`
3. **Дано** станцію, яку не запущено чи в якій доступ вимкнено, **тоді** інструменти мосту не падають, а відповідають простими словами, що зробити («Запустіть станцію», «Увімкніть зовнішніх агентів у налаштуваннях»). Так само про невідомий проєкт чи пакет: зі списком тих, що є.
   Тест: `test/unit/autotests-external.spec.js`
4. **Дано** зовнішнього агента, **тоді** йому доступні лише інструменти цієї фічі: його токен не відкриває інструментів вбудованого агента (змін, керування пристроєм, трафіку й логів), а токен вбудованого агента — інструментів зовнішніх.
   Тест: `test/unit/autotests-external.spec.js`

Інструменти (лише читання)

5. **Дано** `autotests_packages`, **тоді** агент отримує список пакетів screen object проєкту (за замовчуванням активного, або за назвою проєкту): id, назва, дата, платформа, застосунок і версія, скільки screen object і скільки з кодом, чи позначено «Готово для автотестів». Без деталей.
   Тест: `test/unit/autotests-external.spec.js`
6. **Дано** `autotests_package_get`, **тоді** агент отримує screen object пакета (усі чи один за назвою): назву, екран, стани й згенерований код на Kotlin. Усі елементи з локаторами й діями — лише з `elements`, зменшені скриншоти станів — лише з `screenshots`. Пакет, який агент забрав, позначено в станції.
   Тест: `test/unit/autotests-external.spec.js`
7. **Дано** будь-яку відповідь, **тоді** тексти елементів проходять те саме приховування, що й для вбудованого агента ([agent.station-mcp](../agent.station-mcp/spec.md), критерій 15), а відповідь, довша за 60 000 символів, обрізана з підказкою просити по одному screen object.
   Тест: `test/unit/autotests-external.spec.js` (приховування); обрізання — немає

Видимість

8. **Дано** звернення зовнішнього агента, **тоді** воно записується в журнал станції ([station.debug-log](../station.debug-log/spec.md)): інструмент і його аргументи. На картці «Зовнішні агенти» видно, коли й яким інструментом агент звертався востаннє, а в списку пакетів — «Забрав агент».
   Тест: `test/unit/autotests-external.spec.js` (звернення доходять до станції); журнал і картка — немає

## Поведінка й інтерфейс

- Налаштування → «Оператор» → картка «Зовнішні агенти»: перемикач, фрагмент `mcp.json` з «Копіювати», пояснення про міст, останнє звернення.
- У розробці фрагмент запускає зібраний CLI (`npm run build:cli`) через Node з Electron; у встановленій станції — команду `vision-inspector`.

## Безпека й приватність

- Доступ лише з цього Mac і лише після явного ввімкнення.
- Токен тимчасовий і окремий від токена вбудованого агента. Він лежить у файлі з правами лише для користувача, поки доступ увімкнено, і втрачає силу з перезапуском станції. Це не постійний секрет, тож Keychain для нього не потрібен (Keychain ще й прив'язаний до назви застосунку, і міст його не прочитав би).

## Метрика корисності

Кількість пакетів, які забрав агент тестів.

## Відкриті питання

- CLI-варіант (`vision-inspector autotests list | get`) для агента, якому зручніше викликати команду, — тим самим мостом; агент тестів уміє обидва, тож поки лише MCP.
- Чи може агент тестів попросити станцію згенерувати чи перегенерувати код (а не лише забрати готовий).
- Як міст потрапляє на Mac без репозиторію станції: окремий пакет CLI чи команда, яку ставить сама станція.
