# CLI, MCP-сервер і доктор середовища

- **ID:** `access.cli-mcp`
- **Статус:** implemented (частково щодо документа)
- **Етап за документом:** MVP (локальний API, CLI, MCP-сервер)

## Проблема й користувач

Те саме, що вміє станція, потрібне в CI й агентам (Claude, Cursor): перевірити середовище, аудит доступності екрана, аналіз збірки. Команди мають працювати лише з Node.js, без Electron.

## Критерії приймання

1. **Дано** `vision-inspector doctor`, **тоді** виводяться Node.js, Appium і драйвери, Android SDK, adb, Java, Xcode, сервери Appium із сесіями й пристрої, з кодом виходу за проблемами.
   Тест: `test/unit/doctor.spec.js`
2. **Дано** `vision-inspector audit` (або `a11y`) з сесією чи дампом екрана, **тоді** виводиться оцінка й проблеми доступності в тексті чи JSON, з кодом виходу за порогом — для CI.
   Тест: `test/unit/cli-audit.spec.js`
3. **Дано** `vision-inspector build <файл>`, **тоді** виводиться застосунок, версія, підпис і знахідки маніфесту; `--json` — машинний формат.
   Тест: немає
4. **Дано** `vision-inspector mcp`, **тоді** MCP-сервер дає інструменти `doctor`, `audit_screen`, `list_rules`.
   Тест: немає
5. **Дано** проблему середовища (немає драйвера, образ AVD зник), **тоді** доктор пропонує, як виправити, а станція має кнопку виправлення, де це можливо.
   Тест: `test/unit/doctor.spec.js`

## Поведінка й інтерфейс

Доктор показується на робочому столі станції як плитки перевірок і список проблем із кнопками.

## Точка розширення

Інтеграція (для агентів і CI). Код: `app/cli/vision-inspector.js`, `app/cli/mcp.js`, `app/common/node/doctor/`, плагін для Appium у `plugins/`.

## Модель даних

Звіт доктора (перевірки зі статусом і виправленням), звіт аудиту, звіт збірки.

## API, CLI, MCP

Описано вище. Локального API ядра, з якого живляться UI, CLI й MCP (як у документі), немає: CLI й UI викликають ті самі модулі напряму.

## Відкриті питання

- Локальний API ядра й одна схема команд, з якої генеруються UI, CLI й MCP (документ).
- Команди для логів, проксі й збірок у CLI та MCP.
- Назва команди (`vision-inspector`) після вибору назви продукту.
