# Специфікації Station#1

Station#1 — робоча назва робочої станції QA-інженера, яку документ «Grace — список фич» (Pitwall, 26.10.2026) називає Grace Station: одне вікно, де UI, мережа, логи, збірки й доступність мобільного застосунку видно разом, від тикета до релізу. Перша мета, як у документі: щодня замінити зв'язку Appium Inspector + Charles + adb на реальному проєкті під Android та iOS.

Тут лежать специфікації фіч. За документом розробка йде через spec-driven development: жодна фіча не потрапляє в продукт без зафіксованої специфікації, а специфікація — контракт фічі.

## Як працюємо

1. **Пропозиція.** Нова фіча починається з короткого опису: проблема, для кого, чому зараз. Для невеликих змін досить розділу «Проблема» в новій спеці зі статусом `draft`.
2. **Специфікація.** Спека пишеться за [шаблоном](_template.md) у `specs/<id>/spec.md` і погоджується до коду. Статус стає `approved`.
3. **Реалізація.** Агенти й люди роблять строго за спекою. Якщо реалізація відходить від спеки, спершу правиться спека.
4. **Перевірка.** Кожен критерій приймання має тест, і спека посилається на нього. Критерій без тесту позначається `тест: немає` і стає боргом.
5. **Злиття.** Спека, код і тести йдуть одним комітом або MR. Статус стає `implemented`.
6. **Еволюція.** Будь-яка зміна поведінки змінює спеку в тому самому коміті.

Статуси: `draft` → `approved` → `implemented` → `deprecated`.

Правила, які з часом триматиме CI (зараз — домовленість):

- зміна без посилання на спеку не зливається;
- зміна поведінки фічі без зміни її спеки блокується;
- кожен критерій приймання прив'язаний хоча б до одного тесту.

## Що не так, як у документі

- **Назва.** У документі Grace, Grace Station, Pitwall. У продукті поки робоча назва Station#1. Дані застосунку лежать у теці `vision-inspector`, щоб перейменування нічого не губило.
- **Мова.** Інтерфейс український (вимога для першої версії). Англійські рядки є, російської немає.
- **Платформа.** Поки лише macOS: iOS-симулятори й реальні iPhone потребують Xcode. Windows і Linux збираються, але без iOS.
- **Архітектура.** Документ закладає тонке ядро, шину подій і плагіни з першого дня. Зараз фічі вбудовані в застосунок, хоча спільна модель знахідок уже є (`shared/findings`). Перехід на ядро з плагінами потребує окремої спеки.
- **Маскування даних.** Для першої версії не потрібне. Виняток — ШІ: перед надсиланням дані приховуються (ai.screen-check).
