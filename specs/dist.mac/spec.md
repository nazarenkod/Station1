## Проблема й користувач

Станцію ставлять на робочий Mac банку, часто без прав адміністратора, і оновлюють під час налагодження. Вона має ставитися як звичайний застосунок, з власною назвою й значком, а не як Electron.

## Критерії приймання

1. **Дано** клон репозиторію й Node.js, **коли** запущено `npm run install:mac`, **тоді** збирається застосунок під процесор цього Mac (Apple silicon чи Intel, навіть якщо Node працює через Rosetta), закривається запущена копія, ставиться нова й відкривається.
   Тест: немає
2. **Дано** Mac без прав адміністратора, **тоді** застосунок ставиться в `~/Applications` замість `/Applications`.
   Тест: немає
3. **Дано** встановлення без Developer ID, **тоді** застосунок підписано локально (ad hoc) і зняту позначку карантину, щоб він відкривався.
   Тест: немає
4. **Дано** Developer ID і дані нотаризації, **коли** запущено `npm run pack:mac`, **тоді** DMG і ZIP для arm64 та x64 підписано й нотаризовано (`docs/signing.md`).
   Тест: немає
5. **Дано** `npm run dev:electron`, **тоді** в Dock, меню й Cmd+Tab видно Station#1 з його значком, а не Electron (після `npm install`).
   Тест: немає
6. **Дано** значки, **тоді** `npm run icons` будує `.icns`, `.png`, `.ico` і favicon з двох SVG, щоб усюди був той самий знак.
   Тест: немає

## Безпека й приватність

- DMG не кладуться в git (ліміт GitHub 100 МБ, роздування історії); роздавати через GitLab Releases чи внутрішнє сховище.
- Для банку потрібне погодження з безпекою: сертифікат проксі, зміна системного проксі, локальні сервери, токени.
- Видалення: застосунок, тека `vision-inspector` і записи «Safe Storage» в Keychain.
- Код заливається лише в `station` (github.com/nazarenkod/Station1), ніколи в `origin` (upstream appium).
